## System and evidence boundaries

CommerceCore is one modular Spring Boot process with a PostgreSQL store. A separate Payment Service and PostgreSQL store handle provider authorization over TCP gRPC. CommerceCore commits business state and outbox intent locally, then Kafka and idempotent consumers deliver effects at least once. See [architecture](../architecture.md), [guarantees](../guarantees.md), and the [current diagram](../diagrams/architecture.current.svg). These mechanisms protect scoped local invariants; they do not create a transaction across databases or Kafka.

Use an isolated local checkout and disposable test databases. The default offline tools need Python 3; database and Java tests need Java 21, Docker, and the images `postgres:16` and, for M17, `ghcr.io/shopify/toxiproxy:2.9.0`. The Gradle wrapper uses the repository's declared dependencies. M16 capture additionally needs local `psql` and dedicated SELECT-only roles. No step below should point to production. `build/consistency-lab/` is ignored, disposable evidence; keep it private until reviewed, then remove only the generated files you own.

## Interpretation and remaining gates

The M16 snapshots cover four CommerceCore tables and one provider table, independently. They do not capture local payment rows, Kafka delivery receipts, or scenario-level operation identity. Local `UNKNOWN` and provider `AUTHORIZED` can legitimately coexist after a lost response. M17 demonstrates controlled failure paths in an isolated topology, not all real network schedules. M18/M19 cover only reservation and same-key checkout service calls under the declared scope. M20 reduction qualifies the checker with synthetic mutations; a captured application failure remains unavailable. M21 has no provider, database, Kafka, or fault timeline. None of these results establish inventory conservation from a final snapshot, exactly-once delivery, global linearizability, exhaustive distributed correctness, or production readiness.

The historical M21 browser review exercised operation selection, keyboard selection, zoom, 400 px layout, and Chrome print pagination after the print fix. It did not leave a committed screenshot artifact. Reinspect generated HTML in a real browser before presenting it as current visual evidence. Existing [screenshots](../screenshots/) and [diagrams](../diagrams/README.md) are presentation aids, not runtime experiment proof.

Security: the recorders require explicit loopback/test targets and SELECT-only roles; the local qualification checks write denial. Bundles omit connection passwords, raw checkout idempotency keys, and customer records, but still contain test identities and should be reviewed before sharing. M20 hashes provide integrity against isolated edits, not producer authentication. Local generated artifacts are ignored and are not included in this release.
